Architecture

A modular Django REST application

The browser interface is a lightweight client of the same versioned REST API available to Postman and other integrations. Django applies authentication, role permissions, object-level scoping, validation, and persistence.

03
Placement lifecycle

Three placement stages, three report states

Placement

Placed→Active→Completed

An administrator assigns the student, supervisor, track, cohort, and dates. A student can have only one non-completed placement.

Weekly report

Draft→Submitted→Reviewed

A reviewed report may be corrected and resubmitted. It returns to Submitted while retaining the latest supervisor feedback.

When is a report overdue?

Once an expected internship week has ended, the report is overdue if no submitted or reviewed report exists for that placement and week. Drafts do not count as submitted.

Users, roles, email login, JWT, registration, password changes.

Supervisor identity, staff details, contacts, assigned students.

Internship periods, date boundaries, and active status.

tracks

Internship specialisations such as Data Science or Software Development.

placements

Direct assignment joining student, supervisor, track, and cohort.

reports

Weekly work, skills, challenges, submission, review, and feedback.

dashboards

Role-specific statistics, progress, pending reviews, and risk signals.

common

Shared models, validation, errors, pagination, health, and frontend.
